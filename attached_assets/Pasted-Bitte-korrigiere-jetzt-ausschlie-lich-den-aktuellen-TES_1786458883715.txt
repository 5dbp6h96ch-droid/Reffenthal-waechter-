Drei konkrete Anforderungen:

1. PEGEL-AUSWAHL

Die separaten Pegel-Buttons oben auf der Startseite sollen vollständig
entfernt werden.

Pegelstand-Kachel aufgenommen werden.

KEIN Hardcoding.

2. PERSÖNLICHE SCHWELLENWERTE

Der aktuell angezeigte Schwellenwert auf der Haupt-Pegelstand-Kachel
darf NICHT mehr aus den globalen Wächter-Daten kommen.

Aktuell ist dort sinngemäß:

const threshold = state?.threshold_cm ?? 225;

Das ist falsch, weil state Speyer-spezifische Wächterdaten enthält.

Die Schwelle muss aus den persönlichen Einstellungen des aktuell
ausgewählten Pegels kommen:

getGaugeSetting(selectedGauge.id)

und insbesondere:

alert_threshold_cm

verwenden.

Damit gilt:

ausgewählter Pegel = Mannheim
→ persönliche Mannheim-Schwelle anzeigen

ausgewählter Pegel = Worms
→ persönliche Worms-Schwelle anzeigen

ausgewählter Pegel = Speyer
→ persönliche Speyer-Schwelle anzeigen

Die Werte aus „Meine Pegelwarnungen“ und die Schwelle in der großen
Pegelstand-Kachel müssen dieselbe Datenquelle verwenden.

WICHTIG:
Nicht wieder state.threshold_cm verwenden.

Wenn für einen Pegel noch kein persönlicher Eintrag existiert,
verwende einen sinnvollen bestehenden Default, aber KEINE falschen
Speyer-Wächterdaten. Prüfe dabei den vorhandenen Hook
useUserGaugeSettings.ts und die bestehende GaugeAlertRow-Logik und
verwende deren vorhandene Default-/Speicherlogik, sofern vorhanden.

Auch die Alarmberechnung:

isAlarm
isSafe
statusLabel

muss anschließend dieselbe persönliche Schwelle verwenden.

3. HVZ-BW-VORHERSAGE

Die bisherige Zuordnung ist falsch/unvollständig.

Aktuell steht sinngemäß:

const HVZ_BW_IDS = {
  SPEYER: '09017',
  MANNHEIM: '06268',
};

Das muss korrigiert werden zu:

const HVZ_BW_IDS = {
  SPEYER: '09017',
  MANNHEIM: '09001',
  WORMS: '09018',
};

Die offiziellen HVZ-Seiten bestätigen:

Speyer / Rhein → 09017
Mannheim / Rhein → 09001
Worms / Rhein → 09018

Alle drei Pegel haben eine HVZ-Pegelseite.
Bei Worms ist ausdrücklich eine Wasserstand-Vorhersage-Grafik vorhanden.

Die Vorhersage muss daher bei allen drei Pegeln funktionieren.

Die bestehende Logik mit selectedGauge.pegel_nr darf für die
HVZ-Zuordnung weiter verwendet werden:

selectedGauge.pegel_nr.toUpperCase()

PEGELONLINE bleibt dagegen UUID-basiert und darf NICHT wieder auf
pegel_nr zurückgestellt werden.
